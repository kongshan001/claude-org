# 游戏资源防提取/防解包（防"扒库"）技术方案调研报告

- **日期**:2026-09-05
- **类型**:外部调研报告(deep-research 流程:多路检索 → 读源 → 对抗核验 → 合成)
- **范围**:手游+PC 端游,Unity/Unreal/Cocos/自研引擎
- **置信度**:关键声明均多源交叉核验;厂商宣传处已标注"厂商数据";Denuvo 性能影响为公开实测互相矛盾,按场景看待

---

## 〇、核心结论(TL;DR)

1. **资源防护没有银弹,本质是"延迟破解 + 提高成本"**。2026 年 4 月破解社区已攻破**所有**搭载 Denuvo 的非 VR 单机游戏(Hypervisor 绕过方案两周破数十款),PC 端最强商用壳如此——客户端任何防护最终都可被绕过。
2. **威胁分层决定手段**:防"普通玩家/解包党用现成工具"(低成本加密+容器改造即可拦住 90%)、防"外挂作者/私服"(需要服务端权威)、防"内鬼泄露"(靠水印+法律,加密没用)。
3. **性价比最高的三件事**:① 服务端权威校验;② 热更/资源清单签名;③ 高价值资源选择性加密 + 自定义容器。商用全量加固(VMP 级)有真实翻车案例(见 §8)。
4. **防护强度排序(客户端侧)**:XOR 混淆 < AES 整包 < 选择性块加密+目录隐藏 < 自定义格式/VM 化 < 商用壳;**密钥管理决定真实强度**——密钥被抠出,加密全废。

## 一、威胁模型与攻方工具链现状

| 攻击者 | 目的 | 典型手段 |
|---|---|---|
| 解包党/Dataminer | 提前挖未实装内容、盗美术 | AssetStudio/AssetRipper(Unity)、FModel(UE)、UABE |
| 竞品/素材贩子 | 扒美术与数值配置 | 同上 + 换皮 |
| 外挂/私服作者 | 改配置、扒逻辑 | Il2CppDumper + IDA、luadec、内存修改 |
| 内鬼/媒体泄露 | 提前曝光内容 | 截屏/录像/解包测试包 |

**攻方工具已高度自动化**:
- **Unity 系**:AssetStudio/AssetRipper 是纯静态解析器,**不校验 CRC**(很多游戏故意损坏 CRC 防解析,但它们直接解析目录表跳过校验),能跨版本重建 TypeTree、导出 FBX/PNG/可导入工程 → **结论:任何"换皮压缩/损坏 CRC"级别的障眼法都拦不住它们,必须动加密或动格式结构**。
- **UE 系**:FModel(CUE4Parse 引擎)走"Pak 索引 → AES 解密(手动填密钥)→ UObject 反序列化 → 导出"完整管线,覆盖 UE4.18–5.4;另有 AESKeyFinder 类工具直接从游戏 exe 里静态/动态扫出 256 位 AES 密钥 → **UE 官方加密的核心弱点就是密钥躺在可执行文件里**。

## 二、分引擎官方方案

### UE4/UE5(官方能力最完整)
官方文档(UCryptoKeysSettings / FPakSignatureFile / FPakPlatformFile::RegisterEncryptionKey)给出三层模型:
- **AES-256 加密**:开关粒度到文件类型——`bEncryptPakIndex`(加密索引,防 unrealpak 直接改)、`bEncryptUAssetFiles`、`bEncryptAllAssetFiles`(最安全但 IO 慢、不利于热更,官方不建议全开)。多密钥支持(`SecondaryEncryptionKeys`)可对敏感资源单独用不同密钥。
- **RSA 签名(.sig)**:每 64KB 块 CRC + RSA 加密哈希,防篡改防替换(热更 pak 必须带有效签名才能 mount)。
- **UE5 IoStore 时代**(.utoc/.ucas)解析需要 `usmap` 映射文件,是 UE5 资源天然多的一道门槛。
- **核心弱点(多源一致)**:加密/签名密钥编译进游戏可执行文件(`UE_REGISTER_ENCRYPTION_KEY`),换密钥必须重新出包;攻击者用 AESKeyFinder 类工具扫描 exe 即可提取。

### Unity(原生无加密 → 现实全靠自研/第三方)
- **标准 Unity AssetBundle 没有任何内置加密**,AB 结构公开(UnityFS 头),这是 AssetStudio 系工具能横扫的原因。
- **团结引擎(Unity 中国版)官方内置 AB 加密**:`BuildPipeline.SetAssetBundleEncryptKey / AssetBundle.SetAssetBundleDecryptKey` + `EnableProtection`,AES+自定义算法,要求 LZ4 压缩;官方称加密开销约 384 字节/无明显性能差异(⚠️ 厂商数据,接口适用范围以对应版本文档为准)。
- **社区/自研标准路线**(多篇实战一致):
  - 构建后处理加密 → 运行时**流式解密**加载。**关键陷阱**:`LoadFromFile` 走 mmap,加密文件必因魔数校验失败返回 null(iOS 最严格、Android 次之、Windows 最宽松);`DecryptionCallback` 只在 `LoadFromMemory(Async)` 路径触发——加密后必须走内存加载,且解密字节流要与原始 Bundle 完全一致(含 padding)。
  - 头部插垃圾 + `LoadFromFile(path, crc, offset)` 跳过 = 零开销但强度约等于没有。
  - 加密**目录结构本身**(不止内容):易盾方案加密后 AssetStudioGUI 连资源目录都看不到。
- **IL2CPP 脚本侧**(与资源保护强相关,脚本是"密钥/解密逻辑的家"):
  - Mono 打包 = Assembly-CSharp.dll 直接可被 dnSpy 反编译;IL2CPP 编译为原生码 + `global-metadata.dat` 集中存符号,**Il2CppDumper 可用 so+dat 还原出可读的骨架 DLL**。
  - **global-metadata 防护演进(多源一致)**:一代=整包加密、加载时整体解密(弱:解密后完整暴露内存可 dump);二代=**边运行边按需解密片段**,dump 也拼不出完整元数据。
  - **混淆先行**:IL2CPP 前跑 Unity 感知混淆器,让元数据符号失去意义(ACTk 官方文档——引擎插件官方安全文档,威胁模型思路值得抄)。

### Cocos / Laya 等 Lua 系
- 阶梯(腾讯安全实验室漏洞分析、quick-cocos2d-x 加密文档):luac 编译(弱,luadec/unluac 可还原)→ **XXTEA/AES 加密字节码 + 自研加载器**(Cocos 原生支持 XXTEA)→ **自定义 opcode/魔改 VM**(最强,luadec 直接失效,代价是维护成本)。
- 攻方视角(防什么要想清楚):IDA 静态回溯 `luaL_loadbuffer`、Hook 加载函数截取解密后字节码、对比标准 VM 还原 opcode 映射。
- 易盾等商业方案:脚本保护 + 引擎 so 保护 + 资源(png/plist/json)加密打包成一套。

## 三、密钥管理:整套加密的命门

核验结论(多源一致):**所有"密钥硬编码进客户端"的方案最终都会被抠出来**——UE 的 AESKeyFinder、Lua 的 loadbuffer 回溯、Unity 反编译找常量,全是同一件事。强度阶梯:

1. 硬编码常量(最弱,反编译即泄露)
2. 运行时拆分/拼接 + 代码混淆保护(挡一般解包党)
3. **动态下发**:RSA 交换会话密钥 / 每次构建随机密钥 / 每热更包独立密钥 + 定期轮换(泄露不波及全部历史包)
4. **白盒密码(White-Box)**:把密钥藏进查表变换,密钥永不显式出现

⚠️ **白盒的真实水平(对抗性核验)**:公开学术共识——**截至 2023 年没有公开的、不可破解的标准 AES 白盒方案**,已有主流 AES 白盒方案 3 个被代数分析攻破;真正抗攻的是为"不可压缩性"专门设计的专用算法白盒实现。**且即便密钥抠不出,攻击者可以直接执行白盒代码当解密器用**。所以白盒=混淆级防护,商用价值在"提高门槛",别当绝对保险。

## 四、真实厂商做法(公开资料,已区分事实/推测)

- **米哈游(原神 PC)**:内核级驱动 mhyprot2(进程/镜像/线程回调、防注入、每 100 秒完整性校验循环、禁内核调试器)+ 主程序破坏 IAT/混淆。⚠️ **反面教训(多方独立证实)**:Trend Micro 2022 年报告该驱动被勒索软件当 BYOVD 漏洞驱动滥用来杀 AV/EDR;绕过项目(Genshin-Bypass、evil-mhyprot-cli)在 GitHub 公开存在——**重客户端防护 = 攻击面 + 声誉风险,且依然能被绕过**。
- **腾讯系**:反作弊(ACE)+ 加固(乐固)。乐固技术内核经 Quarkslab 独立逆向确认:**DEX 字节码 NOP 掏空(dump 只得到类名)+ NRV 压缩 + 改良 XTEA 加密 + native 层动态回填**,指令抽取思路专打内存 dump 脱壳。资源侧做法=资源加密+文件级完整性校验(改动任何资源文件游戏无法运行)+签名校验+渠道盗版监控。
- **网易**:自用+商用(易盾)一套体系——纯 SO 层方案(不动 DEX 兼容性好)、AB 资源在 so 层动态解密、脚本 DLL 解密、防 Hook/防 Dump/防修改器(行为识别而非进程扫描)、小游戏 wasm/webdata 加密。
- **Denuvo(PC 单机 DRM 代表)**:VM 化代码 + 完整性校验。⚠️ 争议是**防护的代价样本**:性能损失案例(《红色沙漠》约 20% 帧差、《龙之信条2》移除后性能提升)与无损失案例(《黑旗 RE》5090 实测差异≈0)并存——**结论:GPU 瓶颈场景损失小、CPU 瓶颈场景损失真实存在**。

## 五、热更新链路防护(容易被忽略的重灾区)

- **签名是主防线**:补丁/manifest 用 RSA/ECC/**Ed25519** 签名,客户端验签后才应用;manifest 里含每文件哈希。
- **防降级攻击**:严格模式校验低版本覆盖;灰度发布 + 崩溃熔断自动回滚 + 补丁黑名单。
- **与加固的兼容性是个真坑**:Tinker/Sophix 类热更与加固完整性校验天然冲突——需要白名单配置、签名证书必须一致。**Unity 热更 + 加密一体化的通用做法:资源清单签名 + 增量包独立密钥**。

## 六、服务端兜底(性价比之王,但不算"资源防护")

- **铁律:客户端永远不可信**——数值/掉落/伤害全在服务端算,客户端只上报"意图"(我打谁/我捡什么),服务端验证边界(数量、冷却、幂等)后广播。
- 掉落随机数必须 **CSPRNG**(`rand()`/时间戳种子可被复现整个序列);进阶用 VRF 做可验证随机。
- 对"资源防护"的意义:客户端改了贴图/配置只影响自己画面,**改不出收益** → 长线运营游戏最不怕资源被改。

## 七、内鬼/泄露溯源(资源防"人"的方向)

加密防不住截屏/录屏,厂商实际是**技术+法律双轨**:
- **屏幕级不可见水印**(复变函数分形编码叠在画面上,截屏/拍照/录屏都带、模糊化去不掉)+ 文档指纹水印(AI 隐写微调行距/词序,每份文件可生成万亿级唯一版本,EchoMark 类服务已商用)。
- **追责实战**:米哈游内鬼泄密案(00 后博士反编译测试包+建站传播,涉嫌侵犯著作权罪被移送起诉);库洛(鸣潮)起诉 B 站实为**借司法程序调取用户数据定位泄密账号**(2022 年米哈游同款操作);崩铁内鬼线下偷录被判赔 50 万。
- **配套资源侧**:测试包与正式资源分离、每渠道/每人分发唯一 ID。

## 八、代价与取舍(落地必读)

**加固强度实测样本**(单源厂商数据,仅作量级参考):同一 Unity ARPG 820MB 包,20 人团战场景——未加固 54.5fps → 基础混淆 53.8fps(≈0 损耗)→ 企业标准 44.7fps → **全量 VMP 31.2fps**;真实案例某日活 20 万 MMORPG 上全量 VMP 后团战 55→25fps,低端机变 PPT,**三天留存掉 12% 紧急回滚**(⚠️ 竞品单源,方向性可信——与 Denuvo 的 CPU 瓶颈结论互证)。

**主流共识的分级策略**(多源一致):

| 资源类型 | 强度 | 备注 |
|---|---|---|
| 数值/活动/IAP 配置 | 最高+服务端下发 | 直接关系收益 |
| 未实装剧情/付费皮肤/立绘 | AES/自定义容器 | 防提前泄露+盗用 |
| 高频战斗资源 | 轻量/块级加密 | 技能首放卡顿不可接受 |
| 公开 UI/低价值 | 不加密 | 别全量加密 |

选择性**块加密**(只加密核心块+运行时解密)是平衡点:宣称 300 资源解密 <10ms、CPU 影响 <2%(厂商数据);密钥按大版本/资源包轮换,泄露不波及其他包。

## 九、推荐落地优先级(针对"防扒库"目标)

```
L0 免费起步:服务端权威数值/掉落 + 测试包权限管控
L1 必做:热更包/资源清单签名(Ed25519/RSA)+ 完整性校验(manifest 哈希)
L2 重点投入:高价值资源 AES + 流式解密;Unity 走 LoadFromMemory 路径;脚本上 IL2CPP + 符号混淆 + metadata 按需解密
L3 进阶:自定义容器格式(改魔数/结构),卡 AssetStudio 系静态解析;Lua 上自定义 opcode
L4 密钥管理:动态下发 + 每包独立密钥 + 轮换;评估白盒(按威胁等级)
L5 可选:商用壳(易盾/FairGuard/乐固等)——先小流量压测帧率/内存/启动,再决定是否全量
L6 运营侧:屏幕水印 + 分发唯一 ID(防内鬼,加密管不到这里)
```

**分平台差异**:PC 端威胁最重(无沙箱、工具最全)→ 密钥绝不落 PC 端;Android 加固生态成熟但壳会被脱(乐固都被 Quarkslab 逐字节拆了);iOS 相对好(无官方 sideload 大渠道+越狱门槛),别花冤枉钱上重壳。
