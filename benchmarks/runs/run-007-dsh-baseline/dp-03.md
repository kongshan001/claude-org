## 回答
## DP-03 | @deepseek-ai/dsh 版本检测与一键更新方案

**1. 最新版探测:npm registry 直连,双源依次尝试**
依次请求 npmmirror 与 npmjs 的 registry manifest(如 https://registry.npmmirror.com/@deepseek-ai/dsh → https://registry.npmjs.org/@deepseek-ai/dsh),取 dist-tags.latest 作为 latest;前者失败才回退后者,两者皆失败则返回检查失败并保留上次缓存结果。刻意绕开 GitHub API:无 token 时 topic search 接口 403 且整体受限流;npm registry 直接 fetch 不受 GitHub 限流影响,是可靠且简单的最新版来源。

**2. 版本比较:按 semver 处理 prerelease**
用 semver 比较器解析 local 与 latest;核心规则:1.0.1-rc.2 排序低于同号正式版 1.0.1——即 latest 是 rc 而 local 已含更高正式版时不判过时;仅当 latest 严格大于 local 才 outdated=true(rc 默认不自动升级,除非显式 opt-in)。实测基准:local = latest = 0.1.1-rc.2 时应判为已最新。

**3. 状态接口三元组**
暴露 GET /dsh-update-tab/status,返回 { local, latest, outdated }:local 读本地安装版本,latest 来自双 registry 探测结果,outdated 为 semver 比较结论;单接口即可支撑前端按钮态与命令行查询。

**4. 一键更新 + 重启提示**
更新执行:以 npm install -g @deepseek-ai/dsh@latest(或项目内等价升级)拉取并安装,完成后复读本地版本确认。关键提示:主程序/插件更新必须整进程重启才生效(热载只对已加载插件的 patch 改动生效);web 常以孤儿进程运行,需自重生式重启(detached helper SIGTERM 旧进程 → 轮询端口释放 → 同 argv 重拉)。重启后可再查 status 接口验证版本已生效。
