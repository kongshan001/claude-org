# 用例:DSH 插件安装审计方案

- **任务描述**:给一个声称是 bundle 型的 dsh 插件(如 dsh-restart)设计"安装前审计 + 安装 + 验证"方案,不实际执行
- **期望产出**:≤6 步方案,含安全核对、装法、验证法
- **验收点**:
  1. 安全核对包含 package.json 生命周期脚本(preinstall/install/postinstall)与 dsh 字段检查
  2. 装法为 bundle 三步:dependencies + dsh.profile.bundles 末尾追加 + profile 目录 pnpm install
  3. 提到受限 shell PATH 缺 /usr/bin 会导致 git ENOENT 失败(需补 PATH)
  4. 验证 = 整进程重启 + 探测插件路由(404 = 未加载)
  5. peer 依赖警告(react/cordis)是常态可忽略
- **历史得分**:—(baseline 首轮)


## 回答
## dp-01 方案：dsh-restart 插件「审计 + 安装 + 验证」(6 步，不实际执行)

**第 1 步 · 安全核对**
- 检查 package.json 的 preinstall / install / postinstall 生命周期脚本：为空或仅无害操作才算通过；有脚本则逐行审查（禁网络拉取、禁写 $HOME 之外、禁 eval 远程内容），再核对 dsh 字段（插件身份声明）、dependencies 与只写 $DSH_HOME 的写盘范围
- 核对对外动作（如重启按钮 / POST 端点）仅限环回同源，npm registry manifest 与 GitHub 源码比对确认零运行时依赖、无 install 脚本

**第 2-4 步 · bundle 三步装法**
1. 项目 package.json 的 dependencies 追加插件名
2. dsh.profile.bundles 数组末尾追加（顺序即 patch 应用顺序）
3. 在 profile 目录执行 pnpm install
- ⚠️ 受限 shell 的 PATH 缺 /usr/bin 时，pnpm 拉 github: 依赖会因 git ENOENT 失败（exit 254）；先 export PATH="/usr/bin:$PATH"（macOS git 位于 /usr/bin/git）。CLI 失败不会写回 package.json，可安全转手工等价操作

**第 5-6 步 · 验证**
- 整进程重启（孤儿进程需 detached helper 自重生：SIGTERM 旧进程 → 轮询端口释放 → 同 argv 重拉并落盘日志）
- 重启后探测插件路由：GET /plugins/dsh-restart/restart 返回 404 = 未加载，需排查；非 404 即挂载成功
- peer 依赖警告（react / cordis）是常态，运行时由 dsh 提供，可忽略
