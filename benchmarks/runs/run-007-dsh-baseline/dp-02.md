# 孤儿进程 dsh web 快速重启方案

## 1. 进程身份识别
dsh web 常以孤儿进程运行(PPID=1、无看门狗):旧进程一旦退出,没有外部守护会把它拉起来。因此方案必须自重生——由重启动作派生 detached helper 承担"杀旧→等端口→拉新"全流程,不依赖任何外部看门狗。

## 2. 重启流程(6 步)
1. **采集进程身份**:Web UI 点击「快速重启」→ 后端读取当前 node 进程的 pid、cwd 与完整启动 argv(端口/profile 等参数),作为重拉的权威依据;
2. **安全校验**:重启 POST 仅接受环回同源请求(校验来源为 127.0.0.1/localhost 同源),防止恶意网页跨站触发重启;
3. **派生 helper**:spawn(helper, {detached:true, stdio:'ignore', unref()})——detached+unref 使子进程脱离父进程生命周期,父进程退出后 helper 仍存活,保证"自杀式重启"不中断;
4. **终止旧进程**:helper 对旧 pid 发 SIGTERM,记录退出状态;宽限期后仍未退出则升级 SIGKILL;
5. **轮询端口释放**:按 ~200ms 间隔探测监听端口,确认完全释放后再重拉,避免地址占用冲突;
6. **同 argv 重拉 + 日志落盘**:以第 1 步采集的同 argv 重新拉起进程,stdout/stderr 重定向至 ~/.dsh/dsh-web-restart.<timestamp>.log 供排障,helper 完成后自退。

## 3. 失败兜底
- 端口超时(如 30s)未释放 → 中止重拉,保留旧进程状态并写入错误日志;
- 新进程启动即崩溃 → 由端口探活发现,凭落盘日志定位根因;
- 全程零运行时依赖、无 install 脚本,重启动作只读 $DSH_HOME,无外部写面,安全可审计。

**验收点对照**:①PPID=1 → 明确自重生、不依赖外部看门狗;②detached helper 执行 SIGTERM→轮询端口→同 argv 重拉;③spawn(detached:true, stdio:'ignore', unref()) 子进程在父进程退出后存活;④POST 环回同源校验防跨站;⑤新进程日志落盘 ~/.dsh/dsh-web-restart.*.log。
